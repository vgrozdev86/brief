# Бриф-сайт · Виктор Гроздев

Пошаговая анкета для клиентов. Статика: HTML + CSS + JS, без сборщиков. Лежит на GitHub Pages, ответы уходят в Telegram через Cloudflare Worker.

## Файлы

| Файл | Что это |
|---|---|
| `index.html` | разметка, подвал с реквизитами и документами |
| `styles.css` | оформление (стиль как у vgrozdev.tilda.ws) |
| `app.js` | логика. **Вопросы лежат массивом `STAGES` в начале файла** |
| `config.js` | только адрес приёмника |
| `worker.js` | код для Cloudflare. На сайте не используется |
| `politika.html` | политика обработки персональных данных |
| `soglasie.html` | согласие на обработку персональных данных |
| `robots.txt` + `<meta robots>` | закрывают сайт от поисковиков |
| `assets/new_avatar.jpg` | фото на первом и финальном экране |

## Как менять вопросы

В `app.js` найдите `STAGES`. Каждый вопрос: `id`, `key`, `label`, `hint`, `required`, `important`, `type` (`short`, `long`, `links`, `files`, `consent`). Остальной код трогать не нужно.

Настройки в начале `app.js`: `REPLY_TIME` (срок ответа на финальном экране), `TG_URL`, лимиты файлов, `DOC_VERSION` (версия документов, пишется в заявку; меняйте при правке политики и согласия).

## Пока приёмник не подключён

`config.js` с пустым `endpoint`: бриф работает полностью, а вместо отправки предлагает скачать файл с ответами. Ответы не теряются: черновик хранится в браузере, при ошибке отправки остаётся кнопка «Скачать ответы».

## Подключение Telegram

1. @BotFather → `/newbot` → получите токен. Копируйте его целиком, нажатием на сообщение.
2. Напишите своему боту «привет» (иначе он не сможет вам писать).
3. Откройте `https://api.telegram.org/botТОКЕН/getUpdates`, найдите `"chat":{"id":ЧИСЛО`. Это CHAT_ID.
4. Cloudflare → Workers & Pages → Create → Hello World → Edit code → вставьте `worker.js` → Deploy.
5. Settings → Variables and Secrets:
   - `BOT_TOKEN` — токен (Secret)
   - `CHAT_ID` — число (Secret)
   - `ALLOWED_ORIGIN` — только домен сайта, без пути и слеша: `https://ваш-логин.github.io`
6. После добавления переменных нажмите **Deploy** ещё раз.
7. Адрес воркера (`https://brief-bot.….workers.dev`) впишите в `config.js` и опубликуйте сайт заново.

В отличие от версии из методички, воркер **не принимает запросы с других доменов** (если `ALLOWED_ORIGIN` пуст — отклоняет всё). Для проверки с компьютера добавьте в `ALLOWED_ORIGIN` через запятую `http://localhost:8099`, потом уберите.

## Перед тем как давать ссылку клиентам

Это условия законности схемы (подробности в переписке):

- [ ] Поданы уведомления в Роскомнадзор: **об обработке** персональных данных и **о трансграничной передаче** (Cloudflare, Telegram). Дождитесь срока рассмотрения (до 10 рабочих дней) для второго.
- [ ] В `politika.html` и `soglasie.html` проверьте: полные наименования и адреса Cloudflare, Inc. и Telegram FZ-LLC, срок хранения (сейчас 3 года), контакты.
- [ ] В политике написано «аккаунты защищены двухфакторной аутентификацией». Включите её в Telegram, Cloudflare и GitHub, иначе уберите эту строку.
- [ ] Сделана тестовая заявка со своими данными, она пришла в Telegram, файл дошёл.
- [ ] Токен бота нигде не засветился (скриншоты, чаты). Если засветился: @BotFather → `/mybots` → бот → API Token → Revoke.
- [ ] Не забудьте добавить на основной сайт Tilda ссылку на бриф только после запуска.

Документы нужно показывать юристу, если хотите полной уверенности. Я не юрист.

## Шрифт

Сайт использует Inter Tight, как на основном сайте. Если файл `assets/fonts/InterTight-Variable.woff2` лежит в проекте, он подхватится. Иначе используется запасной системный шрифт. Google Fonts намеренно не подключены: они отправляют IP посетителя в Google.

## Проверка локально

```bash
python -m http.server 8099
```

Откройте http://localhost:8099
